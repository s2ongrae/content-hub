# 블로그 통계 자동 수집 — 피클 지시서 (2026-11-19)

> 공개 저장소 문서다. **주소·토큰·로그인 정보를 절대 적지 않는다.**

## 왜 피클인가

네이버 블로그의 **글별 조회수 · 유입 검색어 · 유입 경로 · 성별/연령**은 로그인한 본인에게만 보인다.
콘텐츠허브 서버(GAS)는 로그인할 수 없고, 비밀번호·쿠키를 받지도 않는다(`ERR_SENSITIVE_FIELD`).
그래서 **로그인된 브라우저를 쓸 수 있는 피클이 하루 한 번 읽어서** 허브로 보낸다.
허브의 `#/blog`(📝 블로그 탭)가 그걸 모아 보여 준다. 글 목록·댓글·공감·방문자 수는 허브가 공개 데이터로 직접 가져오므로 피클이 보낼 필요 없다.

```
피클(로그인된 브라우저) ── 네이버 블로그 통계 읽기 ──▶ JSON ── POST blog_stats_ingest ──▶ 허브 GAS ──▶ 시트 ──▶ #/blog
```

## 하루 루틴

- **언제**: 매일 새벽 00:30~06:00(한국). 오늘은 집계 중이라 **어제(KST) 하루치**를 보낸다. `day` = 어제 날짜.
- **어디서 읽나**: 블로그 관리 → 통계. (화면은 바뀔 수 있다 — 아래 '처음 한 번'을 먼저 한다.)

| 읽을 것 | 네이버 통계 메뉴 | 보내는 필드 |
|---|---|---|
| 방문자·페이지뷰(일간) | 조회수 | `daily.visitors`, `daily.pageviews` |
| 글별 조회수(어제) | 조회수 → 인기글 / 콘텐츠별 | `post_views[]` |
| 유입 검색어(어제) | 유입분석 → 검색어 | `keywords[]` |
| 유입 경로(어제) | 유입분석 → 유입경로 | `inflow[]` |
| 성별·연령 | 사용자분석 | `audience[]` (일간이 없으면 최근 7일/30일 기준값을 그날 값으로 보낸다) |

한 번에 다 못 읽어도 된다. **읽은 항목만 보내면** 그 항목만 갱신된다.

## 보내는 법

허브 GAS `/exec` 주소로 `POST`. 본문은 JSON 문자열, `Content-Type: text/plain;charset=utf-8`.
**주소와 API 토큰은 피클의 비밀 저장소에서 꺼낸다**(이 저장소·로그·메시지에 적지 않는다).

```json
{
  "action": "blog_stats_ingest",
  "auth_token": "<토큰: 피클 비밀 저장소>",
  "client_id": "pickle",
  "brand": "daejeon_youth",
  "idempotency_key": "blogstat-daejeon_youth-2026-11-18",
  "payload": {
    "brand": "daejeon_youth",
    "day": "2026-11-18",
    "daily": { "visitors": 37, "pageviews": 90 },
    "post_views": [ { "log_no": "224480755004", "views": 41 } ],
    "keywords": [ { "keyword": "봉명동 냉삼", "count": 12 } ],
    "inflow": [ { "channel": "네이버 검색", "count": 30 } ],
    "audience": [
      { "kind": "gender", "label": "여성", "pct": 61.5 },
      { "kind": "age", "label": "30대", "pct": 44 }
    ]
  }
}
```

- `log_no` = 글 주소 끝 숫자(`blog.naver.com/youth-daejeon/` 뒤의 번호). 6자리 이상 숫자만 받는다.
- `count`·`views`·`visitors`·`pageviews`는 0 이상 정수, `pct`는 0~100.
- `kind`는 `gender` 또는 `age`만. 항목당 **최대 500줄**.
- **같은 날을 다시 보내면 덮어쓴다**(멱등). 실패했을 때 같은 `idempotency_key`로 다시 보내도 안전하다.
- 응답 `data.dropped`가 0이 아니면 형식이 틀린 줄이 버려진 것 — 로그에 남기고 형식을 점검한다.
- `day`는 오늘 이전 400일 안. 미래 날짜는 거부된다.
- 삐약 김메리는 블로그가 없다(`ERR_BLOG_SKIPPED`). **대전 청년(`daejeon_youth`)만 보낸다.**

## 처음 한 번 (실제 화면 확인 — 연습 실행)

허브 쪽은 네이버 통계 화면을 직접 본 적이 없다. 그래서 **첫 실행은 보내지 말고 보여 주기만** 한다.

1. 네이버 블로그 통계 각 화면(조회수·인기글·유입분석 검색어·유입경로·사용자분석)에서 읽은 값을 위 JSON으로 만든다.
2. **서버로 보내지 말고** JSON을 성래 님에게 보여 주고, 화면의 숫자와 맞는지(한두 개) 확인받는다.
3. 맞으면 그 날짜로 한 번 보내고 `#/blog`에서 조회수·검색어가 보이는지 확인한다.
4. 그다음부터 매일 자동.

## 지켜야 할 것

- **읽기 전용.** 블로그 글·설정·이웃을 고치는 동작은 하지 않는다.
- **로그인 풀림·캡차·2단계 인증**을 만나면 **재시도하지 말고 멈춘다.** 포털 오더/알림으로 `NEEDS_HUMAN`("네이버 로그인 필요")을 올리고 끝낸다. 비밀번호를 입력하거나 저장하지 않는다.
- 하루 한 번만. 화면 사이 간격을 두고(몇 초) 사람처럼 천천히 읽는다. 실패해도 하루에 3번을 넘기지 않는다.
- **토큰·주소·쿠키·네이버 아이디 비밀번호를 커밋·로그·채팅에 쓰지 않는다.** 이 저장소는 공개다.
- 읽지 못한 항목은 **숫자를 만들지 않는다.** 그 항목은 아예 빼고 보낸다(허브는 비어 있는 걸 0으로 속이지 않는다).
- 통계 화면이 바뀌어 못 읽으면 임의로 추측하지 말고 어느 화면에서 막혔는지 보고한다.

## 허브가 알려 주는 것

- `#/blog` 위쪽에 **"통계가 N일째 안 들어왔어요"** 안내가 뜬다(2일 이상). 피클 루틴이 멈췄다는 신호다.
- 아직 한 번도 안 받았으면 "아직 안 들어왔어요" 안내와 이 문서 위치가 뜬다.

## 허브 쪽 저장 위치 (참고)

시트 `Blog_Post_Views` · `Blog_Keywords` · `Blog_Inflow` · `Blog_Audience`, 그리고 `Blog_Visitors`의 `pageviews` 열.
첫 전송 때 자동으로 만들어진다. 구현: `gas/Blog.gs` `handleBlogStatsIngest_`, 시험: `gas/test/run.js` [B6].

## 피클에게 그대로 붙여 줄 지시문

> 네이버 블로그 `youth-daejeon` 통계를 매일 읽어서 콘텐츠허브로 보내는 루틴을 만들어 줘. 읽는 건 어제 하루치: 방문자·페이지뷰, 글별 조회수, 유입 검색어, 유입 경로, 성별·연령. 형식과 규칙은 콘텐츠허브 레포 `docs/BLOG_STATS_INGEST.md`를 따라. 처음 한 번은 서버로 보내지 말고 만든 JSON을 나한테 보여 줘서 화면 숫자와 맞는지 확인받아. 로그인이 풀리거나 캡차·2단계 인증이 뜨면 재시도하지 말고 멈춘 뒤 나한테 알려 줘. 토큰·주소는 네 비밀 저장소에서만 쓰고 어디에도 적지 마.
