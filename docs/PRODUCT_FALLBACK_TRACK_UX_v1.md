## 1. 이미지 수집 실패 5단계

| 단계 | 화면에서 | 저장·처리 |
| --- | --- | --- |
| ① 사유 한 줄 | `상품을 자동으로 못 읽었어요` + 사람 말 한 줄(코드 `ERR_XXX` 는 툴팁에만) | `failureReason()` — `js/uiState.js` 문장 표를 먼저 쓰고, 상품 전용 문장(막힌 몰·중복·노트북)을 덮어쓴다 |
| ② 대신 채우기 | `📷 사진 직접 올리기` · `✍️ 핵심 특징 3개 적기` · `🔗 다른 링크로 다시 해 보기` | 사진은 카드에 바로 올린다(`uploadPhoto` → `studio.product.image_files`) — 렌더 문턱(5장)에 그대로 쓰인다 |
| ③ 기본 틀 | `입력한 내용으로 기본 틀 만들기` | 상품명만 있으면 5비트 대본·설명란을 만든다. 사진이 없으면 렌더가 안 된다는 사실을 숨기지 않는다(`basicTemplateGate`) |
| ④ 다시 시도 | `다시 시도할 링크 (N)` — 줄마다 `다시 시도`·`빼기`, `전체 다시 시도`·`목록 비우기` | 브라우저에 남는다(`contenthub.product.retry.v1`, 최대 10건). 같은 상품은 한 줄로 합치고 사유·횟수만 새로 적는다 |
| ⑤ 새로고침 유지 | `이전에 쓰던 입력을 불러왔어요 — 11월 26일 14:20 저장` | 입력·운영 트랙·클립 방식·고른 채널·올린 사진 이름·카드 번호를 0.5초 디바운스로 저장(`contenthub.product.draft.v1`, 7일 뒤 폐기) |

- 저장이 막힌 브라우저(사생활 보호 모드)에서도 화면은 산다 — `saveDraft`/`loadDraft` 는 던지지 않고, 화면이 한 줄로 알린다.
- 초안이 있으면 카드 결과를 자동으로 덮어쓰지 않는다(적던 값 우선). 카드 결과는 버튼을 눌러 다시 읽는다.

## 2. 운영 트랙 A/B

| 트랙 | 브랜드(`brand`) | 상품 링크로 만드는 채널 | 비고 |
| --- | --- | --- | --- |
| A · 대전 청년 | `daejeon_youth` | 블로그 · 쇼츠 · 릴스 · 피드 · 클립 | 첫 사용 기본값 |
| B · 삐약 김메리 | `ppiyak_kimmary` | 쇼츠 · 릴스 · 클립 | 블로그·피드는 해제하고 한 줄로 알린다 |

- 마지막으로 쓴 트랙을 기억한다(`contenthub.product.brandtrack.v1`).
- 탭을 바꿔도 **상품명·사진·핵심 특징 3개는 그대로** — 바뀌는 것은 채널 목록·비율·문구 세트뿐이다(`trackSwitchPlan`).
- 비율: 블로그 `글` · 피드 `4:5` · 쇼츠/릴스/클립 `9:16`. 같은 9:16 이라도 트랙이 다르면 말투·해시태그·행동 한 줄이 다르다(`channelCopy`).
- 설명란 해시태그도 트랙 색을 따른다(`trackTagList` → `descriptionBlocks({tags})`).
- 카드도 브랜드에 속한다 — 브랜드가 다른 카드가 남아 있으면 새 카드로 시작하고 적은 값은 유지한다.
- **클립 방식 A/B(챌린지·쇼핑커넥트 수익화)** 는 `js/productShorts.js` 의 기존 계약 그대로다. 화면에서는 `클립 방식` 줄로 따로 보여 준다(운영 트랙과 섞지 않는다).
