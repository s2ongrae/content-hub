# 콘텐츠 표준 v3 — 하이브리드 경계

> 이 문서는 **v2 규격을 상속하고 하이브리드 경계만 정한다.** `docs/CONTENT_STANDARD_v2.md`의 자막·오디오·영상 규격과 발행 전 판정(기계 6 + 사람 12)은 그대로 유효하고, 이 문서는 그 앞단에서 **AI가 어디까지 만들고 사람이 캡컷에서 무엇을 닫는지**만 정한다.
> 숫자가 어긋나면 v2 문서와 `seeds/render_standard_v2.json`이 우선한다. 이 문서를 고칠 때 `srt_spec`·`clean_spec` 같은 이름으로 코드가 읽지 않는다(현재 참조 없음).

## 1. 역할 경계

| 누가 | 하는 일 | 하지 않는 일 |
|---|---|---|
| AI(노트북 · FFmpeg) | 컷편집, 음량 평탄화, `.srt` 생성, 체크리스트, 제목·본문·해시태그 패키지 | 자막 굽기(번인), TTS 내레이션, 효과음 배치, 커버 프레임 선택 |
| 사람(캡컷) | 폰트·자막 스타일, 안전영역 배치, 강조어, BGM·효과음, 커버 프레임, AI 보조 안내 | 음량을 -14 LUFS 밖으로 옮기기, 자막 3줄 만들기 |

이유는 '심사 회피'가 아니라 **수정 가능성**이다. 자막을 영상에 구우면 폰트·위치·문구를 고칠 때 처음부터 다시 렌더해야 한다. 네이버 클립 공식 기준은 AI 자막을 금지하지 않고 **"보조적 수단으로 AI를 활용한 경우 클립 내 안내를 추가"**를 요구한다(표4).

## 2. 표1 — 클린 마스터 `{content_id}_clean.mp4`

| 항목 | 확정 수치 | 비고 |
|---|---|---|
| 해상도 / 화면비 | 1080 × 1920 · 9:16 | 세로 풀프레임, 검은 레터박스 금지 |
| 프레임 | 30fps CFR | VFR 금지 |
| 비디오 | H.264 High · CRF 18 · yuv420p · MP4 `+faststart` | 2차 인코딩 열화 방지용 마스터 |
| 길이 | 3.0 ~ 90.0초 | 3초 미만·단일 사진·AI 자동 하이라이트 클립은 클립 챌린지 제외. 3분 초과 **수동 편집본**은 인정 |
| 오디오 | AAC 256kbps · 48kHz · 스테레오 | 192k → 256k 상향 |
| 음량 (BGM·효과음 얹을 때) | **-16.0 ± 0.5 LUFS · TP ≤ -2.0 dBTP** | 2.0 LU 여유. 캡컷에서 얹고 최종 -14로 안착 |
| 음량 (자막만 얹을 때) | **-14.0 ± 0.5 LUFS · TP ≤ -1.8 dBTP** | 캡컷 게인 0.0 dB 유지 |
| 넣지 않는 것 | 번인 자막 0건 · AI TTS 0초 · 효과음 0건 · 로고/아웃트로 범퍼 0건 | 캡컷 수정 가능성 보장 |

## 3. 표2 — 자막 `{content_id}.srt`

| 항목 | 확정 수치 | 비고 |
|---|---|---|
| 인코딩 / 줄바꿈 | UTF-8 (BOM 없음) / LF | 캡컷 한글 깨짐 방지 |
| cue 길이 | 1.0 ~ 3.5초 | 12자 인지 최소 시간 ~ 숏폼 컷 호흡 |
| cue 간격 | ≥ 0.06초 (30fps 2프레임) | 0.00초면 임포트 때 클립이 합쳐진다 |
| 무내레이션 오프셋 | 시작 `cut_in + 0.03`초 / 끝 `cut_out - 0.06`초 | 화면 전환과 자막 전환 충돌 방지 |
| 줄당 글자 | 대전 청년 12자 / 삐약 김메리 11자 (공백 포함) | 최대 2줄, 3줄 금지 |
| 문장부호 | 문장 끝 마침표만 제거, 쉼표는 유지 | 2줄로 나뉘는 긴 문장의 호흡 |
| 금지 | ASS 태그(`\an8`·`\c`·`\fad`), 화자 표기, `\k` 카라오케 | 순수 텍스트만 |

## 4. 표3 — 캡컷 7단계 마무리 (약 2분)

| 단계 | 작업 | 캡컷 위치 | 합격 기준 |
|---|---|---|---|
| 1 | 캔버스·내보내기 기본값 | 비율 메뉴 / 우측 상단 내보내기 | 9:16 (1080×1920) · 30fps · 12~15Mbps · 스마트 HDR OFF |
| 2 | 폰트·스타일 일괄 | 텍스트 전체 선택 → 기본 | 대전청년 `Pretendard Bold` / 메리 `NanumSquareRound ExtraBold`(미설치 시 Noto Sans KR Bold / 빙그레체 Bold) · 크기 8~9 · 자간 -2 · 외곽선 `#000000` 9% · 그림자 65% 거리 4 흐림 15% |
| 3 | 안전영역 배치 | 1번 단독 / 2번~끝 일괄 | 훅 `Y = +620`(크기 115%), 본문 `Y = -420`, 좌우 ≥100px, 하단 끝 ≤1420px, 상단 ≥240px |
| 4 | 강조어·페이드 | 자막 더블클릭 / 애니메이션 | 자막당 강조어 1~2개만 브랜드색(#FF7A1A 대전청년 / #E08A56 메리) · 페이드는 첫·마지막 자막만 0.15초 |
| 5 | AI 보조 안내 | 텍스트 추가 + 업로드 본문 | 표4 규칙 |
| 6 | BGM·효과음·최종 음량 | 오디오 → 음악 / 효과음 | BGM 현장음 있으면 -24dB, 없으면 -16dB(끝 1.0초 페이드아웃) · 효과음 -12~-10dB, 30초당 ≤4개 · 내보낸 뒤 `ffmpeg loudnorm` 실측 **-14.0 ± 0.5 LUFS / TP ≤ -1.5** |
| 7 | 커버 프레임·제목 | 타임라인 좌측 커버 | 정사각 1080×1080 안전 구도, 피사체 중앙, 모션블러 0, 눈 감음 0 · 제목 4단어 이내 |

### 표4 — 네이버 클립 AI 보조 안내 (표3 ⑤)

| 항목 | 확정 |
|---|---|
| 언제 | 자막을 AI가 만들었을 때 (사람이 직접 썼으면 불필요) |
| 어디에 | 클립 **마지막 2초**, 하단 안전영역(y ≤ 1420) 안쪽 우측 정렬 |
| 어떻게 | `AI 자막 보조` · 크기 5~6 · 불투명도 70% · 배경 없음 |
| 본문 | 업로드 본문에도 "자막: AI 보조" 한 줄 병기 |

근거: 네이버 클립 공식 유의사항 — "자막 생성, 색 보정 등 보조적인 수단으로 AI를 활용한 경우 해당 내용을 알 수 있도록 클립 내 관련 안내를 추가해 주세요. 단, 클립의 전체 혹은 대부분을 AI를 활용하여 생성한 경우 심사·혜택 지급에서 제외될 수 있습니다."(<https://clipcreators.naver.com/promotion/today>)

## 6. 2026-11-20 개정 — 캡컷 없이 허브 안에서 끝내기 (진행 중)

사용자 결정: 하이브리드(캡컷 마무리)를 없애고 영상 편집·자막·오디오를 전부 콘텐츠 허브에서 한다. 한 번에 바꾸지 않고 단계별로 옮긴다.

| 단계 | 상태 | 어디서 |
|---|---|---|
| 영상 올리기 | **됨(2026-11-20)** | 허브 제작 탭 ① → 구글 드라이브 비공개 폴더 `ContentHubOS_Uploads/<content_id>/`(2MB 조각, `gas/Upload.gs`). 노트북이 렌더 때 받아 간다 |
| 컷편집 | **됨(2026-11-20)** | 허브 ③ 컷 목록(무음·추임새·재시도, 켜고 끄기) → ④ 오더 `cuts` → 노트북 `cut.py --remove --smart` 로 실제로 자른 뒤 9:16·음량 |
| 자막 파일(SRT) | 다음 | Whisper 전사 → 규격 분할 → **허브 화면에서 사람이 문구 확인·수정**(무음에서 문구를 지어내는 문제 때문에 확인 단계가 필수) |
| 자막 굽기 | **됨(2026-11-20)** | 카드 payload `production.captions`([{start,end,text}]) → 오더 `captions` → 노트북이 ASS 를 만들어 `caption.py --ass` 로 굽고 `{content_id}_final.mp4` 를 함께 남긴다. 클린 마스터는 그대로 보존(문구만 고칠 때 컷·SDR·프레이밍을 다시 돌리지 않는다) |
| TTS 내레이션 | **됨(2026-11-20)** | 오더 `narration`([{start,end,text,tone:'hype'|'calm'}]) → 노트북이 `edge-tts`(무료·토큰 0)로 큐마다 목소리를 만들어 타임라인에 얹고, 그 구간만 현장음을 -15dB 덕킹한다(attack 50ms · release 300ms). TTS 가 실패하면 번인만 마치고 `report.tts_fallback_reason` 에 남긴다 |
| BGM | 그다음 | 사용자 BGM 폴더에서 고른 곡을 `audio.py --music --duck`. 현장음 있으면 -24dB, 없으면 -16dB, 끝 1초 페이드아웃, 최종 -14 LUFS |
| 효과음·커버 | 보류 | 커버는 프레임 선택 화면이 필요 |

- **그때까지 위 표의 '다음' 이후 항목은 이 문서 §1~4(캡컷 7단계)가 그대로 유효하다.** 한 단계가 허브로 넘어올 때 이 표를 고치고, 표3 에서 해당 단계를 뺀다.
- 오더 계약: `content_render` payload 에 `cuts` 가 더해졌다(`[from,to]` 또는 `[from,to,파일번호]`, 초, 150개까지 — 큐 payload 4000자 한도). 노트북·GAS·허브가 각자 검사한다.
- 오더 계약(2026-11-20): payload 의 `fit`(`crop` · `blur` · `pad`)이 프레이밍을 정한다. 비우면 노트북이 **원본 화면 방향으로 자동** — 가로(w>h)는 `blur`(가로 화면을 자르지 않고 위아래를 흐린 배경으로), 세로는 `crop`. 그전엔 무조건 crop 이라 16:9 원본이 1080 폭에 맞추느라 가로의 31%만 남았다.
- 색(2026-11-20): 원본이 HDR10/PQ · HLG · BT.2020 이면 노트북이 `color.py --to-sdr`(hable)로 **8-bit SDR BT.709** 로 먼저 바꾼다. 릴스·클립 규격이 SDR 만 받고, fit.py 는 HDR 을 HEVC Main10 그대로 보존하기 때문이다.
- 컷의 시간은 **원본 영상 기준**이다(이미 편집한 영상의 자막을 넣으면 엉뚱한 곳이 잘린다).
