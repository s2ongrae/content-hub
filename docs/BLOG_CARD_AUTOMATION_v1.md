# 블로그 초안 → 허브 카드 자동 반영 v1 (2026-11-24)

초안을 쓰면 **린트 + 허브 카드 + 점수 기록**이 한 번에 따라오게 만든 규칙. 사용자 지시
“자동으로 삭삭 되어야지”(2026-11-24)에 대한 답이고, 2026-11-23에 생긴 구멍(피클 체험기가
네이버 임시저장에는 있는데 허브 카드에는 없는 상태)을 다시 만들지 않기 위한 것이다.

## 0. 한 줄 규칙

> 블로그 초안을 만들었으면 **같은 작업 안에서** `tools/blog_card_cli.py --apply`까지 돌린다.
> 카드 없는 초안, 린트 안 돈 카드는 “끝난 것”이 아니다.

## 1. 명령 하나로 끝내기

```bash
# 이미 있는 카드에 초안 반영 (본문·제목·해시태그·blog.lint·quality_score)
python3 tools/blog_card_cli.py draft.md --card DY-20261121-001 --photo 7 --env hub.env --apply

# 새 카드로 만들면서 바로 반영 (create_content → update_content)
python3 tools/blog_card_cli.py draft.md --new --place "진미오겹살 본점" \
    --category "숯불구이 · 오겹살" --cluster "대전 맛집 · 괴정동 오겹살" \
    --keywords "대전 괴정동 맛집, 진미오겹살" --photo 7 --env hub.env --apply

# 서버에 쓰지 않고 점검만 (기본값 — --apply 가 있어야 쓴다)
python3 tools/blog_card_cli.py draft.md --card DY-20261121-001 --photo 7
```

- `--env` 파일은 `URL=…` / `TOKEN=…` 두 줄(각 기기의 `hub.env`, `work/circus3/hub.env`와 같은 형식).
  없으면 환경변수 `HUB_URL` / `HUB_TOKEN`.
- 도구는 `tools/blog_lint_cli.py`의 `lint()`를 그대로 쓴다 → **웹 `#/lint`(js/blogLint.js)와 같은 규칙·같은 점수**.
  (2026-11-24부터 `test/run.js [13]`이 두 곳의 판정이 어긋나는지 시험한다.)
- 쓰는 값: `payload.blog`(title·body·hashtags·lint·lint_checked_at) + `Contents.quality_score` + `blog_title`.
  다른 payload 칸(사진·임시저장 정보·메모)은 건드리지 않는다.
- `expected_version`을 보내므로 다른 기기가 먼저 고쳤으면 `ERR_VERSION_CONFLICT`로 멈춘다(덮어쓰지 않음).

## 2. 초안 파일 형식

```markdown
# [대전 괴정동 고기집] 진미오겹살, 집게 한 번 안 들고 먹은 후기
본문 첫 줄…
```

첫 `# ` 줄이 제목, 나머지가 본문이다(`tools/blog_lint_cli.py split_draft`).

## 3. 2026-11-24에 고친 린터 판정 (웹·CLI 동시)

| # | 무엇이 문제였나 | 어떻게 바꿨나 |
|---|---|---|
| 1 | 해시태그 12개를 한 줄에 쓰면 `54자 초과`로 감점 (6건 중 4건) | 해시태그 줄은 길이·덩어리 판정에서 뺀다 — 마지막 한 덩어리가 규칙(`docs/LINE_BREAK_v1` §5) |
| 2 | 소제목(▍ ■ ◆ ** 1. 1) ①)·구분선(━)·인용 줄을 `한 줄 덩어리`로 셈 | 문서 규칙(§4 예외)대로 구조 줄은 고아 판정에서 뺀다 |
| 3 | 사진 자리(`[사진: …]`)·링크 카드 표시(`[LINK_CARD: …]`)를 글자 줄로 셈 | 네이버에서는 사진·카드 한 장이라 판정에서 뺀다 |
| 4 | 정보 카드 머리 `📊🏦💡`가 정보 줄로 인식되지 않아 카드가 낱줄로 쪼개짐 | `INFO_HEAD_RE`에 📊📈🏦💡💳 추가 |
| 5 | 쇼핑 커넥트 고지(`수수료를 제공받습니다`)를 체험·협찬 **대가**로 오인 → 제휴 글이 “대가 표시 없음” 경고 | 고지 문장을 빼고 대가 표현을 세고, 제휴 고지는 통과로 본다(`PROFIT_NOTICE_RE`) |
| 6 | 맛집 기준(제목 앞배치·첫 화면 정보·핵심 태그 `대전맛집/유성맛집/봉명동맛집`)을 모든 글에 강제 → 스마트스토어·주식·앱 체험기가 30~50점 | **장소 글**(지역 + 메뉴 낱말)일 때만 강제, 아니면 같은 항목을 안내(`near`)로 낮춘다. 카드가 `requiredTags`를 주면 그대로 검사 |
| 7 | CLI에 공개 표시 3항목·링크 카드 3항목이 아예 없었음 | 웹과 같은 15항목으로 맞춤(가중치 0, 정책 경고는 `pass`를 막음) |
| 8 | CLI `도로명` 판정이 `판매자로` 같은 말을 도로명으로 잡음 / 링크 카드 정규식이 줄 단위라 `[LINK_CARD:]`를 못 찾음 | 번지 숫자를 요구(`~로 12`) / 토큰 정규식으로 분리 |

## 4. 남는 것 (사람이 정할 일)

- **사진 밀도**: 기준 `사진 16장↑ · 장당 85~130자`. 초안 단계에서 사진을 16장 넣기 전에는 항상 경고가 남는다.
- **본문 분량**: 기준 `1,700~2,300자`. 2,500자를 넘으면 경고 — 내용을 자를지는 사람이 정한다(자동으로 자르지 않는다).
- **키워드 과반복**: 같은 낱말 6회 이상이면 발행 보류(`hold`). 상품명이 반복되는 글은 문장을 손보거나 기준을 조정해야 한다.
- **대가 표시 위치**: `앞 400자`(본문 맨 위)가 원칙. 맨 아래에만 있으면 “본문 뒤쪽 표기” 안내가 남는다.
