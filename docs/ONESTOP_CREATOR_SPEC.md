## 2. 원칙 6 (설계 불변식)

1. **툴이 계산하고 조립한다.** 슬롯·조립은 서버·LLM 없이 브라우저 순수 함수. 피클(에이전트)은 재료를 넣고 오더를 내리는 손이다.
2. **원문 불변.** 사용자가 쓴 문단은 `USER` 블록으로 읽기 전용 격리. 조립기는 앞(`SYSTEM_HEAD`)·뒤(`SYSTEM_TAIL`)·블록 사이 미디어만 끼운다. 조립 직후 `sha256` 재검증, 불일치면 저장 거부.
3. **0초 조립 + 노트북은 심화·실행만.** 노트북이 꺼져 있어도 5채널 초안은 그 자리에서 완성된다. 노트북은 ①영상 렌더 ②업로드 ③(선택)카피 다듬기를 맡는다.
4. **채널별로 쪼갠다.** `#/create` 안에서 블로그·쇼츠·인스타(릴스/피드)·클립·당근을 각각 고르고, 그 채널 규격표·슬롯·출력물만 본다. 조립기도 `composeBlog / composeShorts / composeClip / composeDaangn / composeInstagram`, 공통 코어(`facts`+`blocks`+`sha256`)는 하나.
5. **링크는 카드다.** 교차링크·관련링크를 줄글 URL로 남기지 않는다. 네이버 에디터 링크 카드(OG 임베드)로만 넣는다(§6.3).
6. **실패해도 작업이 멈추지 않는다.** 오더 전송이 실패해도 조립본은 이미 저장·복사 가능. 화면은 배너 + 복구 버튼 3개(§8.3).

## 3. 화면 `#/create`

### 3.1 라우트·탭
- 탭바 `글감`(`data-route="capture"`)을 **`만들기`(`data-route="create"`)** 로 바꾼다. 탭 개수는 9개 유지(360px 가로 스크롤 0).
- 옛 링크 `#/capture`는 `#/create`로 리다이렉트(기존 글감 폼은 `#/create`의 `빠른 글감` 접이식으로 그대로 살린다).
- `app.js` `renderRoute()` 매핑에 `create → renderCreateView` 한 줄, `index.html`에 `<script type="module" src="js/createView.js?v=20261119">` 경로는 app.js가 import한다(현 구조와 동일).

## 4. 데이터 모델 (payload 안에만)

Sheets `Contents` 칸은 **늘리지 않는다**(37칸 유지). 아래는 Drive `payload_{content_id}.json`에 들어간다.

```json
{
  "facts": { "place_name": "", "region_dong": "", "category": "", "cluster_id": "",
             "naver_place_url": "", "hours": "", "closed_days": "", "parking": "",
             "wait_time": "", "price_menu": "", "tel": "", "receipt_verified": false },
  "media_manifest": {
    "folder_url": "", "sync_source": "AUTO_DRIVE|MANUAL", "synced_at": "",
    "items": [ { "id": "m01", "name": "01_외관.jpg", "kind": "PHOTO|VIDEO",
                 "orientation": "PORTRAIT|LANDSCAPE|SQUARE|UNKNOWN",
                 "dur_sec": null, "taken_at": "", "assigned": ["BLOG_STEP2","IG_FEED_1"] } ]
  },
  "slot_guide": { "generated_at": "", "brand": "daejeon_youth",
                  "channels": { "blog": [], "shorts": [], "ig_reels": [], "ig_feed": [], "clip": [], "daangn": [] },
                  "warnings": [ { "code": "PHOTOS_SHORT", "msg": "" } ] },
  "assembly": {
    "status": "DRAFT|BASE_READY|ASSEMBLY_FAILED",
    "user_body_sha256": "",
    "blocks": [ { "id": "B01", "origin": "SYSTEM_HEAD|USER|SYSTEM_TAIL", "immutable": true,
                  "text": "", "media_ref": null } ],
    "outputs": { "blog": {}, "shorts": {}, "clip": {}, "daangn": {}, "ig_reels": {}, "ig_feed": {} },
    "last_order_id": "", "last_error": ""
  }
}
```

파생 규칙(시트 status): `DRAFT`(재료만) → `GENERATING`(오더 실행 중) → `REVIEW`(조립본 준비) → 기존 `READY` 이후 흐름 그대로. 실패는 `NEEDS_HUMAN`(기존 값)로 보낸다.

## 5. 채널별 규격·슬롯 룰 (값은 `js/slot-engine.js`에 상수로 고정 — 화면·파이썬 도구가 같이 읽을 때만 `seeds/`로 뺀다)

슬롯 엔진은 **결정론적**이다: 촬영시각 오름차순 + 종류/방향 + 메모 문단 수로만 배정하고, 모자라면 모자란 대로 배정한 뒤 경고를 남긴다.

### 5.1 네이버 블로그 (`blog`)
| 항목 | 값 |
|---|---|
| 사진 | 18~22장 균등 분배(장당 95~120자). 부족하면 있는 만큼 + `PHOTOS_SHORT` 경고 |
| 배치 | 1~2번 외관·주차 → 3번 메뉴판 → 중간 기본찬·불판·고기 단면 → 마지막 2장 먹조합·영수증 |
| 제목 | `[동네 메뉴] 상호명 솔직후기 : "한 줄"` 26~45자, 앞 14자에 지역+메뉴 |
| 구조 | `SYSTEM_HEAD`: 인사 1줄 + 도입부(원문) + **정보 카드**(📍위치 ⏰영업 🚗주차 ⏳대기 💰가격 ☎전화) |
| 본문 | `USER` 문단 순서 그대로. 문단 사이에 사진 1장 + 빈 줄. **문장 수정 0건** |
| 다장소(코스) 글 | 장소 섹션마다 `📍 n차: 상호 / 한 줄` 블록으로 시작, 섹션 끝에 `📌 영업정보` 카드. (레퍼런스 `224459297302` 실측 형태) |
| 꼬리 | `SYSTEM_TAIL`: 한 줄 결론(원문 마지막 문장 재사용) + **링크 카드 1~2개** + 해시태그 10~12개(핵심 3개 필수) |

### 5.2 유튜브 쇼츠 (`shorts`)
| 항목 | 값 |
|---|---|
| 길이 | A 25초 6비트 / B(메리) 15초 4비트 |
| 컷 | 총 14~20컷, 한 샷 3초 이내, 평균 1.2~1.8초 |
| 미디어 | 세로 영상 우선 5~8개 → 14~20컷 분할. 영상이 3개 미만이면 고화질 사진 3컷까지 보조 + `NEED_CROP` 태그 |
| 자막 | A Pretendard 68px·12자/2줄·하단 안전선 73.9%, B 나눔스퀘어라운드 64px·1줄 중앙 |
| 음량 | -14.0 LUFS / TP -1.5 dBTP, BGM -18dB, 무내레이션 우선 |
| 출력 | 컷시트 표(비트·시간·파일·화면·자막) + 제목 + 고정댓글 문안 |

### 5.3 인스타 릴스 / 피드 (`ig_reels`, `ig_feed`)
| 항목 | 릴스 | 피드(카드뉴스) |
|---|---|---|
| 미디어 | 쇼츠와 같은 세로 컷 공유(15~30초) | 가로·4:5 사진 5~8장(1번 메인 클로즈업 표지, 2번 메뉴판, 3~6 디테일, 끝 가격·위치 요약) |
| 텍스트 | 첫 2줄 훅 + 저장 유도 1회 | 슬라이드별 표지 카피 + 캡션 |

## 6. 조립기 규칙

### 6.1 블로그 — 말투 보존 골격
레퍼런스(사용자가 직접 고친 `224459297302`)의 실제 순서:

```
[인사 1줄]  안녕하세요, …
[도입]      원문 첫 문단 (그대로)
[정보 카드]  📍 1차: … / 📌 영업정보(🕘🚫🍴🅿☎) / 지도 카드
[본문]      원문 문단 그대로 + 사진 1장/문단
[코스면]    📍 2차: … → 본문 → 📌 영업정보 …
[꼬리]      🎥 24초 요약(숏폼 링크) → 👉 같은 편 링크 카드 → #해시태그 10
```

- 원문 문단은 **빈 줄(`\n\n`) 단위**로 쪼개 `USER` 블록으로 만든다. **블록 안의 한 줄바꿈은 그대로 둔다**(두 줄 호흡 보존).
- 조립기는 `USER` 블록의 문자열을 **읽기만** 한다. `origin==='USER'` 블록을 쓰려는 코드 경로는 만들지 않는다(Object.freeze).
- 조립 직후 `sha256(USER블록.join('\n\n'))` === `user_body_sha256` 을 확인하고, 다르면 저장을 거부하고 원문만 남긴다.
- 정보 카드·링크 카드·해시태그는 **추가만**. 기존 문장을 다듬는 버튼(`AI 다듬기`·`고쳐 쓰기`)은 만들지 않는다.

### 6.2 블로그 링크 카드 규칙 (필수)
- 링크는 **카드 1개 = URL 1개**. 줄글 URL 텍스트 금지.
- 조립기 출력은 **설명 한 줄 + 토큰** 두 줄이다(레퍼런스 글 `224459297302`의 형태):
  ```
  👉 같은 봉명동 술상 편: 미미삼겹 냉삼 솔직후기
  [LINK_CARD: https://blog.naver.com/youth-daejeon/224480755004]
  ```
- 설명 줄은 15~35자, **대상 글의 핵심 주제를 그대로 부른다**. `여기·링크·클릭·참고·바로가기` 금지, 5자 미만 금지.
- 개수 1~2개(시리즈 교차 1 + 대표 1). 0개면 배너로 "관련 내 글 1개 선택 권장", 3개 이상이면 린터 경고.
- 화면은 토큰을 카드 모양으로 그리고 `[URL 복사]` + 붙이는 순서 4단계를 같이 보여준다.
- 발행 절차(노트북·사람 공통, 자동 발행 시 필수):
  ① 카드 앞 설명 한 줄 입력 후 Enter → ② **URL만** 붙여넣기 후 Enter → ③ 네이버 에디터가 OG 링크 카드를 만들 때까지 최대 3초 대기(카드 DOM `se-oglink` / `se-module-oglink` 확인) → ④ 카드 위·아래에 남은 일반 URL 텍스트 줄을 지워 **카드 블록만** 남긴다.

### 6.2-1 링크 카드 실태(실측)
- `224459297302`(석암) = **기준**: `👉 같은 봉명동 술상 편: 미미삼겹 냉삼 솔직후기` 뒤에 링크 카드.
- `224480755004`(미미삼겹) = 아직 `▶ 봉명동 다른 고기집 / 석암생소금구이 후기 / https://blog.naver.com/…` 처럼 **URL 줄글**. 린터가 잡아야 할 실제 위반 사례. 리뉴얼 때 카드로 바꾼다.

### 6.2-2 생성 모드 톤 레퍼런스 (필수)

원문이 없거나 부족해 **새로 쓸 때**는 `seeds/skills/tone_reference_v1.md`가 유일한 문체 기준이다(석암·미미삼겹 두 원글 전문 실측, 2026-11-18).

| 모드 | 언제 | 본문 규칙 |
|---|---|---|
| `preserve` | 사용자 원문이 있음 | 원문 글자 그대로 + 앞뒤 추가만 (sha256 잠금) |
| `draft` | 원문이 없거나 1~2줄뿐 | 톤 레퍼런스로 새로 쓴다. 사용자가 적어 준 줄은 **그대로 살린다** |

`draft`가 지키는 5가지(톤 시드 §9): ① 두 줄 덩어리 3개 이상 ② 숫자는 입력값과 동일 ③ 자폭·직설 1~2회 ④ 금지어 0건 ⑤ 링크는 카드.
로컬 비유는 대전 사람이 바로 아는 것(성심당·유성온천·트램·계룡산·갑천·대전역) 안에서만 고르고, 한 편 1~2개.
거친 표현은 **원문 인용만** — 생성 모드에서 새 욕설·비하를 창작하지 않는다.
노트북 LLM에 초안 보강을 맡길 때도 이 파일 경로를 프롬프트에 넣어 같은 제약을 건다.

## 8. 툴 ↔ 노트북(`hub-agent`)

### 8.1 경로
```
브라우저(#/create)  ──api.post('hub_order')──▶  content-hub GAS
                                                    │ ScriptProperties의 큐 토큰
                                                    ▼
                                        CommandQueue /exec  (queue_enqueue)
                                                    ▼
                                        집 노트북 daemon → engine=freellmapi
```
- 브라우저에는 큐 토큰을 절대 넣지 않는다(CSP `connect-src`도 그대로).
- GAS ScriptProperties: `QUEUE_EXEC_URL`, `QUEUE_TOKEN`.
- 타입 화이트리스트: `content_render`(영상 렌더), `content_upload`(업로드), `content_stats`(지표 수집), `blog_neighbor`(댓글·서이추). 그 외는 `ERR_INVALID_ACTION`.

### 8.2 오더 규격
- `engine: "freellmapi"` **명시**(auto 금지: claude 한도·agy 권한 문제로 계속 실패).
- 파일 1~2개, 프롬프트 2,000자 이내, 실행 5분 컷. 넘으면 쪼갠다.
- `mode: "edit"`은 승인 대기(HIGH) → 15분 내 승인 필요. 승인 UI는 포털 오더함/`queue_decide`.

### 8.3 실패 UX (Q5 답)
조립본은 이미 저장돼 있으므로 화면을 초기화·잠금하지 않는다. 주황 배너:
`⚠️ 노트북 오더 전송 실패 — 슬롯 가이드와 원문 보존 조립본은 이미 저장되었습니다`
버튼 3개: `[오더 다시 보내기]`(같은 멱등키) · `[조립본 바로 복사]` · `[실패함으로 보관]`(`assembly.status='ASSEMBLY_FAILED'`).

## 11. 리스크 / 미해결
- **링크 카드는 HTML이 아니라 에디터 조작**이다. 자동 발행 시 URL 붙여넣기→Enter→카드 확인을 단계로 넣지 않으면 카드가 안 생긴다. 실패 감지(카드 셀렉터 `se-oglink`, `se-module-oglink`) 후 재시도 1회.
- GAS Drive 스캔은 Drive 고급 서비스(Drive API)가 켜져 있어야 가로/세로·영상 길이를 얻는다. 꺼져 있으면 파일명 패턴 → `UNKNOWN` 처리(슬롯은 세로 우선 규칙에서 제외하고 사진으로 취급).
- freellmapi의 5분 컷: `js/createView.js`가 커지면 O5를 2개로 쪼갠다(파일 경계는 `createView.js` 상단부/하단부가 아니라 **입력부 1파일 + 결과부 1파일**로 나눈다).
- `#/board`는 payload를 읽지 않으므로 조립 상세는 카드 상세 시트에서 `get_content_detail`로 볼 때만 보인다. 보드에 배지를 달려면 별도 오더 필요.
