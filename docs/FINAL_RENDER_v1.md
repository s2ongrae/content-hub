# 완제품 렌더 v1 — 허브 오더 하나로 자막·내레이션까지

사용자 지시(2026-11-20): "추가해 근데 긴것도 그냥 작업 다 되면 좋을거같은데" · "영상 만든거 너무 짜쳐 … 음성 들어가면서 설명하듯이 해줬어야지 … '와 오토바이들 대박이에요!! 3대가 돌아가요' 막 하면서 호들갑 떨어야지".
→ 컷·9:16·음량만 맞춘 **클린 마스터**에 더해, 오더 하나로 **자막 번인 + 내레이션 + 덕킹**까지 마친 `{content_id}_final.mp4` 를 만든다.
설계는 콘텐츠 허브 전용 제미니 고정방(`콘텐츠 허브 프로젝트 관리`)과 2026-11-20 합의한 확정안(Q1~Q11)을 따른다.

## 1. 산출물

| 파일 | 내용 | 언제 |
|---|---|---|
| `{content_id}_clean.mp4` | 컷 · 9:16 · HDR→SDR · 음량 -14 LUFS/TP -2.0 · **자막·내레이션 없음** | 항상 |
| `{content_id}_final.mp4` | 클린 마스터 + 내레이션(있으면) + 자막 번인(있으면) | 자막이나 내레이션이 있는 오더 |
| `report.json` | `subtitles_burned` · `caption_count` · `sub_style` · `caption_error` · `tts_used` · `tts_voice` · `tts_cues` · `tts_spoken_s` · `tts_failed_cues` · `tts_tempo_cues` · `tts_fallback_reason` · `clean_path` · `final_path` | 항상 |

클린 마스터를 지우지 않는 이유: 문구·톤만 고칠 때 컷·SDR·프레이밍을 다시 돌리지 않고 오디오·자막만 다시 만든다(15분 영상 기준 수정 시간 70% 절감).

## 2. 오더 계약 (`content_render` 확장)

| 필드 | 모양 | 기본 | 비고 |
|---|---|---|---|
| `captions` | `[{start,end,text}]` 또는 `[start,end,text]` 또는 SRT 문자열 | 없음 | 400큐까지 · 큐당 200자 · 초 단위 |
| `narration` | `[{start,end,text,tone}]` · `tone` = `hype` \| `calm` | 없음 | 300큐까지 · 큐당 120자 |
| `narrate` | `true` | 없음 | 대본이 없을 때 **자막 문장을 차분한 톤으로 읽는다** |
| `burn_subtitles` | `false` | 자막이 있으면 굽는다 | 클린 마스터만 원할 때만 `false` |
| `sub_style` | `auto` \| `shorts` \| `long` | `auto` | 180초 기준 자동 |
| `payload_source` | `inline` \| `drive` | `inline` | 큐가 40개를 넘거나 payload 가 3,800자를 넘으면 자동으로 `drive` |
| `voice` | edge-tts 보이스 이름 | 트랙 기본(대전 청년 `ko-KR-InJoonNeural`, 삐약 김메리 `ko-KR-SunHiNeural`) | 큐별 `voice` 가 우선 |

- **긴 영상**: 인라인은 40큐(자막+내레이션 합)까지. 그보다 많으면 `payload_source:'drive'` 로만 보내고 노트북이 허브 GAS `get_content_detail` 로 카드 payload 의 `production.captions` · `production.narration` 을 읽는다(문장을 자르지 않는다). 카드에 그 키가 없으면 FAILED + 안내.
- **검증 분담**: 허브(브라우저·GAS)는 모양·길이·톤·보이스 이름·크기(3,800자)를 막고, 노트북이 초 범위·겹침(앞 큐 끝을 다음 시작 0.05초 앞으로 당김)·정렬·폴백을 맡는다.

## 3. 자막 스타일 (1080×1920)

| 항목 | 숏폼(<180초) | 긴 영상(≥180초) |
|---|---|---|
| 폰트 | Pretendard Bold (없으면 Noto Sans CJK KR Bold 로 대체) | 같음 |
| 크기 | 68px(폭의 6.3%) | 56px(5.2%) |
| 줄 | 한 줄 12자 · 2줄 (고아 단어는 앞 줄에서 단어를 내려 균형) | 한 줄 16자 · 2줄 |
| 위치 | 하단 중앙, 자막 밑단 y=1419(높이의 0.739) | 같음 — 가로 원본의 가운데 화면(y≈656~1264)을 가리지 않는다 |
| 가독성 | 외곽선 3px(#111111) + 그림자 1px, 본문 흰색(#FFFFFF) | 같음 |
| 타이밍 | 페이드 {\fad(80,60)} · 최소 0.8초 보이게(다음 큐 앞까지) | 같음 |

- **반투명 박스는 쓰지 않는다(실측 결정)**: 확정안은 `BorderStyle=3` + `&H66000000` 박스였지만, 로컬 프레임에서 두 줄이 **줄마다 따로 상자**로 보여 지저분했다(박스 불투명도도 66%가 아니라 거의 검정으로 렌더). 외곽선 3px 이 밝은 무대·음식 클로즈업에서도 충분히 읽혀 외곽선으로 확정.
- 강조어 색(트랙 A `#FF7A1A` · 트랙 B `#E08A56`)은 **아직 자동으로 넣지 않는다** — 문장 안 특정 단어를 색칠하려면 큐에 강조 표시가 필요하다(다음 단계: `**단어**` 표기 → ASS 인라인 색).
- "AI 자막 보조" 안내(표준 v3 표4)는 클립 업로드 화면/발행 문구 담당 — 번인 자체는 문구를 넣지 않는다.

## 4. 내레이션 · 덕킹

- **엔진**: `edge-tts`(무료 · 토큰 0 · 네트워크 필요). 큐마다 mp3 → 48kHz mono WAV → 앞뒤 무음 정리 → 큐보다 길면 `atempo` 최대 1.25배. 4개씩 병렬 생성 후 타임라인에 배치(`narration_full.wav`).
- **톤**: `hype` = rate +18% · pitch +6Hz · volume +10% / `calm` = rate +8% · pitch +0Hz · volume +0%. 문장부호(`!!`, `~`)와 감탄사는 **문장 그대로** 살린다(우리가 문장을 고치지 않는다).
- **덕킹**: 내레이션 구간의 현장음만 **-15dB**(attack 50ms · release 300ms, 말 시작 50ms 전부터 당김). PCM 에서 게인 엔벨로프를 직접 만든다 — `audio.py --duck` 은 양을 15/30/45 로 올려도 실측 깊이가 -5dB 에서 멈췄다(2026-11-20 로컬 측정).
- **음량**: 덕킹·믹스 **뒤에** loudnorm 2패스(-14 LUFS / TP -2.0, 256k 실패·±0.5 이탈 시 320k). 클린 마스터는 내레이션 없이 따로 한 번 더 잰다.
- **실패 처리**: TTS 5초×2회 실패 → 나머지 큐로 계속 → 전부 실패하면 **자막 번인만** 마치고 `tts_fallback_reason` 을 남긴다(전체 실패 아님). 현장음 분리·믹스·교체 실패도 같은 방식.
- 로컬 TTS 폴백(piper 등)은 아직 넣지 않았다 — 노트북에 설치돼 있지 않고, 실패 시 번인만으로도 완제품이 나오게 두었다.

## 5. 파이프라인 순서

```
컷(cut) → 정보 읽기(probe) → HDR→SDR(color) → 9:16 fit/join
  → [내레이션: TTS 큐 생성 → 현장음 분리(audio) → 덕킹 믹스(PCM) → 영상에 교체(audio --replace)]
  → 음량 2패스(클린) [+ 내레이션본 음량 2패스]
  → 자막 굽기(caption --ass)
  → 검수(check, -14/-1.8)
```
영상 재인코딩은 fit·번인 2회로 끝난다. 2026-11-20 로컬 실측(29.6초 세로 원본·HDR, 1080×1920): HDR→SDR 22초 · 세로 변환 67초 · 내레이션 5큐 11초 · 음량 2회 11초 · 자막 굽기 71초 · 검수 1초 → **FAIL 0 / WARN 1, -13.7 LUFS, TP -1.9**.

## 6. 알려진 한계 (다음 단계)

1. 강조어 색·카라오케(단어별) 없음 — 문장에 강조 표시가 생기면 ASS 인라인 색으로 넣는다.
2. 허브에서 자막·내레이션을 **편집하는 화면**은 아직 없다. 카드 payload 의 `production.captions`·`production.narration` 을 읽어 오더에 싣기만 한다(대본 화면은 ⑤ 자막 파일 단계와 함께).
3. Whisper 전사(SRT 자동 생성)는 여전히 '준비 중'.
4. 네이버 클립은 "AI 자막 보조" 안내·AI 비율 가드가 있어, 클립용은 번인 없이 `clean.mp4` 를 쓰거나 안내 문구를 넣는 쪽으로 판단이 남아 있다.
5. TTS 폴백(로컬 piper) 미구현 — 네트워크가 끊긴 노트북에서는 내레이션 없이 번인만.
