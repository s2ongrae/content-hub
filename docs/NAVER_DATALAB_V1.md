> **한 줄 규칙: 발행 전에 '지금 오르는 말인지'를 본다. 숫자는 절대 검색량이 아니라 **주제어마다 그 묶음의 최고점을 100으로 둔 상대값**이다(공식 문서: "구간별 결과에서 가장 큰 값을 100").**

## 1. 이 앱은 스스로 천장을 박았다

무료가 끝나도 **유료 구간에 물리적으로 들어갈 수 없게** 만들었다(`gas/Insight.gs`).

| 종류 | 일 천장 | 월 천장 | HUB 월 한도 대비 | 캐시 |
|---|---|---|---|---|
| 검색어 트렌드 | 200건 | 2,000건 | 4% | 12시간 |
| 쇼핑 인사이트 | 100건 | 1,000건 | 2% | 12시간 |

- 카운터는 `ScriptProperties` 의 `INSIGHT_<종류>_D_<YYYY-MM-DD>` · `_M_<YYYY-MM>` 이고,
  `LockService.getScriptLock().tryLock(3000)` **안에서 확인 → 차감**한다(동시 호출에도 안 샌다).
- 천장에 닿으면 `ERR_INSIGHT_BUDGET` 만 돌려주고 **UrlFetchApp 을 부르지 않는다**(호출 0회).
- 같은 요청(같은 기간·같은 묶음)은 `CacheService` 에 12시간 보관 — 캐시면 카운터도 안 쓴다.
- 통신 오류로 끝난 호출은 미리 차감한 1회를 돌려준다.
- 실제로 밖에 나간 호출만 시트 `Insight_Log` 에 1줄 남는다(캐시 적중은 안 남는다).

## 2. 화면

`#/blog` → **키워드 트렌드 카드** (검색 순위 카드 아래)

- 키워드 5개까지 한 번에(쉼표). **한 요청에 묶어** 보낸다 — 따로 부르면 100의 기준이 달라 비교가 안 된다.
- 줄마다: 키워드 · 계절 뱃지 · `최근 4주 +34%` · 판정(오르는 중/비슷함/내리는 중) · `지금 78 / 기간 최고 100` · 12칸 막대.
- 360px 에서도 접히지 않게 그래프 대신 **3줄 숫자 + 12칸 막대**(96px)로 만들었다.
- 문구: "숫자는 절대 검색량이 아니라 그 키워드 묶음 안에서 가장 높았던 구간을 100으로 둔 값입니다."

## 4. 쇼핑 인사이트 (`insight_shopping`) — API 는 열어 두고 화면은 아직 안 붙였다

- 같은 GAS 액션으로 분야(카테고리 `cat_id`) 최대 3개까지 클릭 추이를 돌려준다.
- **스마트스토어 판단에는 아직 쓰지 않는다.** 이유 두 가지:
  1. 중분류 단위 상대지수(0~100)라 위탁몰 개별 SKU 의 소싱 해상도가 안 나온다.
  2. 가격·경쟁 시세는 API 로 못 하므로(쇼핑 검색 종료) **등록 전 최저가 실측은 사람이** 해야 한다.
- 붙일 때의 규칙(확정): **승격** = 자사 유입·전환 증가 + 분야 4주 이동평균 +15% 이상 + 수동 시세 마진 통과.
  **중단** = 30일 자사 노출·클릭 0 + 8주 연속 하락. **판매 중인 SKU 는 인사이트 하락만으로 중단하지 않는다.**

## 5. 켜는 순서

1. `gas/Insight.gs` 추가, `Auth.gs`·`Code.gs` 최신본으로 교체(화이트리스트·라우터 3줄).
2. 저장 → 배포 → 배포 관리 → 편집 → **새 버전**(URL 유지).
3. 편집기에서 `insightSelfTest()` 1회 실행 → 실행 기록에서 `trend.code`·`shopping.code` 가 200 인지 확인.
   (`NAVER_CLIENT_ID`·`NAVER_CLIENT_SECRET` 은 이미 들어 있다. 값은 로그에 남기지 않는다.)
4. 라이브 https://s2ongrae.github.io/content-hub/#/blog → 키워드 2~5개 → [추이 보기].
