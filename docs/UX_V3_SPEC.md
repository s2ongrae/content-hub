## 1. 절대 규칙 (저장소 CLAUDE.md/AGENTS.md 위에 추가)

- `innerHTML`·`insertAdjacentHTML`·`document.write` 금지. DOM은 `createElement`/`textContent`/`createElementNS`만.
- **대전 청년 팔레트는 손대지 않는다.** 바뀌는 곳은 `html[data-brand="ppiyak_kimmary"]` 블록, `:root`의 신규 채널 변수, 그리고 아래에서 지정한 컴포넌트 CSS뿐.
- `gas/`·`seeds/`·`tools/`·`docs/M2_ROADMAP.md` 수정 금지. 시트 컬럼·GAS 액션 추가 금지(이번 배포 범위 밖).
- 새 라이브러리·외부 폰트·외부 요청 금지(CSP 유지). 이미지 파일 추가 금지 — 아이콘은 인라인 SVG.
- **저장되지 않는 입력칸을 만들지 않는다.** 서버 액션이 없는 새 필드(조회수 입력 등)는 이번에 넣지 않는다.
- 화면 문구는 쉬운 한국어. 코드값(DRAFT·PUBLISHED·SKIPPED)은 화면에 노출 금지. 이모지·배지 추가 금지 — 색·여백·정렬로 해결한다.
- 폰 360px에서 가로 스크롤이 생기면 실패다(AGENTS.md §8).

## 2. 김메리 팔레트 교체 — CSS 변수만 바꾼다

이유: 지금은 bg `#170f12`(적갈색) + surface `#241820` + accent `#ff8fa3`(고채도 핑크) + 14% 핑크 글로우가 겹쳐, 어두운 화면에서 색이 번지고 카드 경계가 사라진다(대비 surface/bg 1.09:1).

`html[data-brand="ppiyak_kimmary"]` 블록을 아래 값으로 교체한다.

| 변수 | 기존 | 신규 |
|---|---|---|
| `--bg` | #170f12 | **#141210** |
| `--bg-soft` | #1d1317 | **#1a1714** |
| `--surface` | #241820 | **#221e1a** |
| `--surface-2` | #2e1f28 | **#2a2521** |
| `--line` | #432c37 | **#3f382f** |
| `--line-soft` | #35232c | **#312b26** |
| `--tx` | #fdeef0 | **#f4efe8** |
| `--tx-2` | #d3b3ba | **#c2b8ac** |
| `--tx-3` | #9d8189 | **#968b7e** |
| `--accent` | #ff8fa3 | **#e08a56** |
| `--accent-2` | #ffc2cc | **#f0b58d** |
| `--accent-ink` | #2a0a12 | **#141210** |
| `--accent-soft` | rgba(255,143,163,.14) | **rgba(224,138,86,.06)** |

검증된 대비비(WCAG 2.1, 내가 직접 계산): `--tx` on bg 16.34:1 · `--tx` on surface 14.47:1 · `--tx-2` on surface 8.47:1 · `--tx-3` on surface 4.96:1 · `--accent-ink` on `--accent` 7.06:1 · `--accent` on surface 6.26:1 · surface/bg 1.13:1 · line/surface 1.43:1. 전부 AA 이상. **이 숫자를 낮추는 방향으로 값을 바꾸지 않는다.**

또 하나: `html[data-brand="ppiyak_kimmary"] body`의 배경 그라디언트에서 두 번째 라디얼(핑크 틴트)을 제거하고 첫 글로우만 `var(--accent-soft)`로 남긴다. `rgba(255,194,204,.07)` 같은 하드코딩된 핑크는 남기지 않는다(전부 변수 기반으로).

`index.html`의 `<meta name="theme-color">`는 지금 `#0b1220` 고정이다. `applyBrand()`에서 브랜드에 따라 `content`를 `#0b1220` / `#141210`으로 바꾸게 한 줄 추가한다(안드로이드 상단바 색이 트랙과 어긋나던 문제).

## 3. 채널 칩 — 카드 앞머리에서 채널이 바로 보이게

### 3-1. 채널 정체성 (`:root`에 추가, 두 트랙 공통)

| 채널 | 변수 | 색 | 아이콘(12×12, stroke 1.5, round) |
|---|---|---|---|
| 블로그 | `--ch-blog` | #5ca36e | 문서 사각 + 안쪽 두 줄 |
| 쇼츠 | `--ch-shorts` | #d96b6b | 둥근 사각 + 재생 삼각형 |
| 릴스 | `--ch-reels` | #b0729e | 사각 + 대각 클래퍼 줄 2개 |
| 인스타 피드 | `--ch-feed` | #7686c9 | 2×2 그리드 사각 4칸 |
| 클립 | `--ch-clip` | #4ea885 | 대각 클립(번개) |

이 색은 **아이콘 선·1px 테두리·12% 틴트 배경**에만 쓴다. **글자는 항상 `var(--tx)`**(10.5px에서 4.5:1 확보). 릴스·피드·쇼츠 색을 글자색으로 쓰면 12% 틴트 위에서 4.0~4.4:1로 AA 미달이므로 금지.

### 3-2. 칩 규격

- 5칸 고정, 순서 `[블로그][쇼츠][릴스][피드][클립]`. **김메리 트랙도 5칸** — 블로그를 숨기지 않고 "건너뜀"으로 보여 준다(두 트랙 카드 모양이 같아야 비교된다).
- 한 칸 = 12px 아이콘 + 2글자 라벨(블로그/쇼츠/릴스/피드/클립), 높이 22px, radius 7px, padding 0 5px, gap 3px, `min-width:0`로 360px에서도 한 줄 유지.
- 상태 4종:
  - **완료**(`UPLOADED`/`DONE`/`PUBLISHED`/`LINKED`): 배경 16% 틴트, 테두리 `color-mix(in srgb, 채널색 55%, transparent)`, 라벨 끝에 작은 ✓.
  - **미시작**(값 없음/`PENDING`): 배경 투명, 테두리 1px dashed `var(--line)`, 아이콘·라벨 `var(--tx-3)`.
  - **실패**(`FAILED`/`PARTIAL_FAIL`): 배경 `var(--danger)` 12%, 테두리 1px solid `color-mix(in srgb, var(--danger) 55%, transparent)`.
  - **건너뜀**(`SKIPPED`): 배경 투명, 테두리 1px solid `var(--line-soft)`, 라벨 대신 `—`(opacity .5).
- 상태 배지(고채도)와 충돌하지 않게 채널 칩은 **저채도 + 작은 면적**만 쓴다. 카드 1행은 상태, 3행은 채널.

### 3-3. 채널 표시 함수 교체

`chanDots(item)`를 없애고 `renderChannelRow(item, brand)`로 바꾼다. 반환: 5칸 칩 + (왼쪽 `var(--spacer)`) + 우측 완료 분수 `n/대상`.
- 대상 수: 대전 청년 5, 김메리 4(블로그 제외) — 분모만 다르고 칸은 5개.
- 완료 판정은 위 "완료" 상태와 동일.
- `quality_score`는 1행 우측으로 옮긴다(3행 분수와 겹치지 않게).

## 4. 카드 3행 압축 (`contentCard`)

1행: `[상태 배지] [모노 content_id] … [growth_tag] [품질점수]`
2행: 제목(13.5px, 최대 2줄, `-webkit-line-clamp` 대신 CSS line-clamp + overflow 춤)
3행: `renderChannelRow()` (5칸 칩 + 우측 n/대상)
4행: 지역·분류·v(버전)을 3행 아래 **한 줄 11px `--tx-3`**로 합친다(지금 3행+4행이 두 줄인 것을 한 줄로). 카드 padding 11px → `10px 11px`, 행 간격 6→5px.

목표: 폰 360px에서 카드 한 장이 지금보다 낮아져 한 화면에 4~5장.

## 5. 상세 시트 — 2탭 (분석 / 원문·메타)

`index.html`의 `#detail-dialog` 안, 제목(.sheet-head) 아래에 탭 바 컨테이너를 둔다: `<div class="sheet-tabs" id="detail-tabs" role="tablist">`. 탭은 JS에서 만든다(버튼 2개, `role="tab"`, `aria-selected`). 기본 진입은 **분석**.

### 탭 1 「분석」 — 전부 지금 데이터로 계산(서버 불필요)

1. **다음 할 일** — 결정론적 규칙, 위에서부터 첫 2개만. 각 항목은 한 줄 문구 + (있으면) 이동 버튼.
   - R1 `status`가 `NEEDS_HUMAN`/`PARTIAL_FAIL` → "직접 풀어야 해요 — 원인을 확인하세요" (버튼: 원문·메타 탭)
   - R2 채널 중 `FAILED` 있음 → "N개 채널이 실패했어요 — 다시 올려 주세요"
   - R3 `status`가 `PUBLISHED`인데 대상 채널 중 기록 없음/`PENDING` 있음 → "아직 안 올린 채널: {이름들}"
   - R4 `quality_score` 없음 또는 80 미만 → "품질 점수 {없음/점} — 80점 이상이어야 올릴 준비로 갑니다" (버튼: 원문·메타 탭)
   - R5 `target_keywords` 비어 있음 → "검색 키워드가 비었어요" (버튼: 원문·메타 탭)
   - R6 `status`가 `DRAFT`/`REVIEW`이고 `updated_at`이 7일 이상 전 → "{N}일째 그대로예요"
   - R7 대상 채널 전부 완료인데 `status`가 `LINKED` 아님 → "'발행 끝'으로 넘기면 보드가 정리됩니다"
   - R8 위 어느 것도 아님 → "지금 손댈 것은 없어요"
2. **진행률** — `n/대상` + 가로 진행 바(완료 채널색 그라디언트, 미완성분은 `var(--line)`).
3. **품질 점검 4줄** — 각 줄은 `통과` / `미달` / `확인 못 함` 세 상태만 쓴다. 지어내지 말 것.
   - 품질 점수 80점: 값 있으면 판정, 없으면 "아직 안 매김".
   - 첫 2초 훅 12자: `payload`에서 훅/커버 문구를 찾아 글자수 판정. **키 이름은 확정되지 않았다** — `hook_text`·`hook`·`cover_text`·`first_line`·`subtitle_first` 순으로 시도하고, 없으면 "확인 못 함".
   - 인트로 0초: payload에 해당 정보가 없으면 "확인 못 함".
   - 팩트 슬롯 `[ ]`: payload의 원고/대본 문자열에 `[ ]`가 남아 있으면 "미달 — 촬영 당일 채울 자리가 남았습니다", 없으면 "통과", payload 자체가 없으면 "확인 못 함".
   - payload가 빈 객체이거나 `{version, updated_at}`뿐인 행(발행 기록 가져오기)이 실제로 있다 → 이때는 4줄 모두 "확인 못 함"으로 두고, 위에 "대본 파일이 없어 품질 점검을 할 수 없어요" 한 줄을 붙인다.
4. **채널별 현황** — 5행(또는 기록 있는 것 전부). 각 행: 왼쪽 3px 컬러 바(채널색) + 아이콘 + 채널명 + 상태 배지 + 기록된 URL이 있으면 링크(`target=_blank` `rel=noopener noreferrer`).
5. **한 줄 안내(성과 지표)** — `--tx-3` 11.5px: "조회·저장·댓글 수는 아직 앱이 자동으로 받아오지 않아요. 다음 업데이트에서 직접 적는 칸이 생깁니다." **입력칸은 만들지 않는다.**
6. 기존 상태별 버튼(확인 완료 / 발행 끝으로 넘기기 / 점검하러 가기)은 이 탭 맨 아래에 그대로 둔다.

### 탭 2 「원문·메타」 — 지금 있는 것을 그대로 옮긴다

- 기존 `kv`(가게·제목·지역/분류·키워드·품질점수·수정)
- 기존 메타 보정 폼(키워드·품질점수 저장) — **동작 그대로 유지**(update_content)
- payload JSON 원문은 `<details>`(기본 접힘) 안에 2400자까지. `innerHTML` 금지, `textContent`.
- 같은 주제 지난 글, 적용 중인 노하우.

전환은 `clear(body)` 후 다시 그리는 방식으로 하고, 저장 후 재열기 흐름(openDetail 재호출)은 유지한다. 탭 상태는 열 때 항상 '분석'.

## 6. 보드 — 비어 보이는 문제

1. **0건 컬럼 압축(폰·PC 공통, 순서는 그대로)**: 카드가 0건인 컬럼은 본문을 렌더하지 않고 한 줄 바로 만든다. 폰(≤699px) 36px, PC 44px. 컬럼명 + `0` + (힌트는 숨김). 기존 `.col.is-empty` 규칙을 이 사양으로 교체.
2. **칼럼 순서는 바꾸지 않는다** — `글감·초안 → 내용 확인 → 올릴 준비 → 일부만 올라감 → 발행 끝 → 내가 봐야 함`은 발행 파이프라인 그 자체이고, `내가 봐야 함`(경고 칸)을 아래로 내리면 경고가 숨는다.
3. 카드 정렬은 `updated_at` 최신순 그대로 둔다(자동 정렬로 카드 순서가 바뀌면 "방금 고친 카드"를 찾기 어려워진다).
4. PC ≥1100px 3열은 그대로. 0건 압축만으로 첫 화면에 카드가 보이게 된다.
