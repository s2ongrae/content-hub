# 모바일 터치·입력 규칙 v1 (2026-11-26)

keyring2 보고(Q-20261126-133755-ly8k) 기준: `#/create/blog` · `#/create/video` · `#/create/product` ·
`#/perf` 를 폰에서 쓸 때 손가락으로 누르기 작고, 입력칸 글자가 작아 iOS 가 화면을 확대하던 문제.

## 규칙

| 항목 | 값 | 이유 |
|---|---|---|
| 누르는 것(버튼·칩·탭·요약) | 최소 **44px** | W3C 2.5.5 / Apple HIG |
| 입력칸(text·url·number·select) | 높이 44px, 글자 **16px** | 16px 미만이면 iOS 가 포커스 때 확대 |
| 두 칸 배치 | 699px 이하 폼은 1열, 420px 이하 격자(`prop-grid`)·스튜디오 카드·성과 숫자 줄 1열 | 375px 에서 두 칸은 손가락·글자 모두 좁다 |

* 좁아서 44px 를 그대로 줄 수 없는 곳은 **보이는 크기는 그대로 두고 히트 영역만** 넓힌다.
  * 상단 바 아이콘: 40px 상자 + `::after { inset: -2px }`
  * 사진 정렬(‹ › ×): 36px + `::after` 위아래 −4px
* CSS 는 `css/style.css` 끝의 `모바일 터치·가독성` 블록과 `css/studio.css` 끝의 `폰 터치·입력` 블록에 있다.
  `studio.css` 가 나중에 실리므로 `.st-*` 는 studio.css 에서 덮는다(같은 선택자면 나중 파일이 이긴다).

## 화면별

* `#/create/blog` · `#/create/video` · `#/create/product`: 사진 올리기·톤 칩·모드 버튼 44px,
  사진 한 줄 메모 입력 16px, 360px 에서 사진 타일 3장(104px) 유지, 영상 모드 버튼은 세로 배치.
* `#/perf`: 숫자 입력 한 줄에 필드 하나(`.mrow` 1열), 저장 버튼 전체 폭, 새로고침 44px.
* 표(table)를 쓰지 않고 flex/grid 만 쓴다 — 360px 가로 스크롤 0 은 그대로 유지한다.

## 시험

`test/run.js [13] ⑨` 가 정적으로 확인한다: 16px 입력, 44px 규칙, 히트 영역 확장, 420px 1열 블록,
영상 모드 세로 배치. 실제 기기(iOS Safari) 자동 확대 여부는 배포 뒤 실기기에서 확인해야 한다.
