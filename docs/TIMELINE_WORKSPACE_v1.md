# 무엇을 만들었나

③ 컷 목록 단계 위에 **시각 타임라인 작업공간**을 붙였다. 영상을 보면서 in/out 을 끌어 자르고,
컷마다 다른 클립을 갈아 끼우고, 재생 위치에 자막·구간 제목이 어떻게 얹히는지 바로 본다.

**프런트엔드만 바꿨다.** `gas/`·시트·노트북(`content_render` 계약) 변경 0, GAS 재배포 불필요.

| 기능 | 자리 | 값이 사는 곳 |
|---|---|---|
| 영상 열기·재생·스크럽·확대(1~40×) | `js/timelineView.js` | 이 기기 메모리(저장 안 함) |
| 컷 in/out 드래그 · 새 구간 긋기 · 합치기 | `js/timeline.js` + 뷰 | `state.cut_list[i].from/to` |
| 컷 끄기·빼기 | 뷰(고른 컷 상자) | `state.cut_list[i].on` / 목록에서 제거 |
| 컷마다 클립 교체 | 뷰(고른 컷 상자) | `state.cut_list[i].clip`(0부터 파일번호) |
| 자막 트랙 · 재생 위치 겹치기 | 뷰(캔버스 1080×1920) | 확정 자막(⑤ `srt_final`) 또는 카드 자막 |
| 양방향 동기화 | `produceView.bodyCuts` | 표 ↔ 타임라인, 둘 다 `cut_list` 하나 |

# 계약 — 오더는 그대로다

- 예전 카드: `cuts: [[from,to], …]` (영상 1개) — 글자 하나 바뀌지 않는다.
- 영상이 2개 이상: 예전에도 `cut_input` 하나를 파일번호로 붙여 `[[from,to,file], …]` 로 나갔다.
  이제 **컷마다** `clip` 을 고를 수 있고, 없으면 예전처럼 `cut_input` 을 쓴다.
  → `content_render` 의 `cuts` 계약, `gas/Orders.gs` 의 `hubRenderCuts_`, 노트북 파서 모두 그대로.
- 새 키·새 액션·시트 열 추가 **없음**(`gas/Orders.gs` 에 `clip`·`MANUAL` 문자열 0건 — 시험 [22]가 확인).

지켜지는 한도(기존과 같다): 컷 150곳 · 한 구간 3,600초 · 영상 8개 · 최소 길이 0.2초(타임라인이 새로 거는 하한).

# 규칙 — 타임라인이 하는 약속

1. **원본은 `cut_list` 하나.** 타임라인은 목록을 고치고, 목록(표·대본 계산)이 바뀌면 다시 그려진다.
   새 저장 키를 만들지 않는다(`studio.formats.video.cut_list` 그대로 — 카드 payload 크기 그대로).
2. **겹치면 합친다.** 새로 그은 구간이 기존 컷과 겹치거나 맞닿으면 한 덩어리로 합치고, 합친 구간에
   서로 다른 클립이 섞이면 파일번호를 비운다(기본 영상) — 어느 영상의 초인지 모호해지지 않게.
3. **손잡이는 이웃을 넘지 않는다.** 앞 컷의 끝·뒤 컷의 시작·영상 길이 안에서만 움직이고, 0.2초 아래로는 줄지 않는다.
4. **자막 경계에 붙는다.** 0.12초 안에 자막 시작·끝이 있으면 그 자리로 스냅한다(자막과 컷이 어긋나지 않게).
5. **컷의 시간은 그 컷에 고른 영상의 원본 시간**이다. 컷마다 클립을 바꾸면 같은 초라도 다른 장면일 수 있으니
   화면에 "이 컷의 영상"을 늘 보여 준다.

# 왜 드라이브 영상을 바로 재생하지 않나

①에서 올린 영상은 **비공개 드라이브**에 2MB 조각으로 있다. 브라우저가 그 주소로 재생할 수 없고(CSP·인증),
조각을 전부 받아 이어 붙이면 폰에서 수백 MB 를 메모리에 올려야 한다. 그래서 미리보기는
**이 기기에서 고른 같은 파일**로만 한다(⑥ 글자 디자인의 배경 미리보기와 같은 방식, 업로드 없음).
시간은 원본 파일 기준이라 노트북이 같은 이름의 파일을 잘라도 컷 위치가 어긋나지 않는다.
