## 1. AI 티 8패턴 — 판정 규칙

| # | 패턴 | 기계 판정 | 판정 |
|---|---|---|---|
| 1 | 일반론 서론 | 앞 150자에 1인칭·숫자·고유명사(지역/영문)·검색어가 모두 0개 | WARN |
| 2 | 대칭 소제목 | 소제목 3개↑ + 글자수 편차 ±2자(최대-최소 ≤4) 또는 모든 소제목이 같은 두 글자로 끝남 | WARN |
| 3 | 결말 상투어 | 마지막 2문단에 `도움이 되셨/기대해 봅니다/응원합니다/마치겠습니다/알아보았습니다/이상으로 정리` | **FAIL** |
| 4 | 균일 문장 길이 | 문장 8개↑ + 문장 길이 표준편차 SD < 6.0 | WARN |
| 5 | 수치 없는 주장 | 문단 8개↑ + 숫자가 든 문단 비율 < 15% | WARN |
| 6 | 1인칭 부재 | `나·내·제·저·우리` + 경험 표현(직접·써보니·가보니·느낀)이 톤 프리셋 하한 미만 | **WARN** (FAIL 아님) |
| 7 | 과잉 친절 | `물론·다만·참고로·혹시라도·부담 없이·편하게` 4회 초과 | WARN |
| 8 | 번역투 | `~에 대해·~에 대한·~를 통해·~할 수 있습니다·~것이 중요합니다·결론적으로` 등이 **4회 이상** (본문 300자 미만이면 판정 보류) | WARN |

**8번째 패턴(번역투, 2026-11-23)**: 세는 것만 한다. 문장을 자동으로 고치지 않는다 — 고치는 사람은 성래 님이다(`humanizer` 스킬도 같은 취지다). 세는 표현은 `seeds/blog_lint_rules_2026w48.json`의 `aiTone.translationese_terms` 한 곳에 있고, 웹앱과 CLI가 같이 읽는다.

**발행 보류(`hold`)**: ① FAIL이 하나라도 있거나 ② WARN·FAIL 합계가 2개 이상이면 `#/lint`·`#/create/blog` 상단에 빨간 배너로 표시한다. 글이 지워지거나 막히지는 않는다 — 고칠 곳을 알려줄 뿐이다.

## 2. 첫 400자 D.I.A.+ 게이트

네이버는 **C-Rank(계정)** 와 **D.I.A.+(문서 의도 적합도)** 두 축으로 본다. 글 쪽은 첫 400자에서 의도가 잡혀야 한다(B2: 질문-답-조건-대상-결론).

| 요소 | 보는 곳 | 판정 신호 |
|---|---|---|
| 질문·문제 | 첫 400자 | `?` · `나요/인가요/을까` · `궁금·고민·헷갈` · `찾는다면·고를 때` |
| 답 | 첫 400자 | `답이다/정답/결론은/바로 이/추천한다/괜찮다/낫다` |
| 조건 | 첫 400자 | `면·라면·경우·평일·주말·예약·주차·가격·웨이팅·영업` |
| 대상 | 첫 400자 | `분들·초보·직장인·커플·혼밥·가족·야근` |
| 결론 | 첫 400자 (없으면 마지막 2문단까지) | `추천·재방문·또 갈·다음엔·총평·한 줄` |

5요소 중 **4개 이상 = 통과**, 3개 = 주의, 2개 이하 = 고칠 것. 결론만 본문 끝에 있으면 '주의'로 두고 "첫 400자에 한 줄 요약"을 권한다.

## 3. 키워드 3~5회 (B3)

노리는 검색어를 넣으면 본문 등장 횟수를 센다. **0회 = 고칠 것 · 1~2회 = 주의 · 3~5회 = 통과 · 6회↑ = FAIL(발행 보류)**. 소제목 등장 횟수도 같이 보여준다(소제목 2곳 권장). 과반복은 오히려 감점이다.

## 4. 우리 판단으로 바꾼 것 (제미니안 → 실제)

1. **소제목 인식**: 우리 에디터는 `###`가 아니라 **굵은 한 줄**을 쓴다. `**…**`·`# …`·이모지로 시작하는 줄을 강한 소제목으로, 22자 이하·문장부호 없는 줄을 약한 소제목으로 본다. 강한 소제목이 3개 이상이면 그것만 센다(캡션·감탄 줄이 섞이는 것을 막는다). `▲ 캡션`·`[사진]` 줄은 소제목이 아니다.
2. **균일 문장 길이는 '문장'으로 잰다**: 우리 2줄 호흡 표준(`BLOG_TONE_v5.md`)이 **문단을 32~44자로 일부러 고르게** 만들기 때문에, 제미니안대로 문단 SD를 재면 정상 글도 매번 걸린다. 패턴의 의도(문장이 다 비슷비슷하다)는 문장 단위가 맞다.
3. **1인칭 부재는 WARN + 톤 프리셋별 하한**: 성래 님 자조·정보 정리 톤은 1인칭이 적어도 정상이다. 하한은 `jajo 1 · review 2 · info 1`(기본 2). FAIL로 두면 정상 글이 계속 막힌다.
4. **점수와 분리**: 8항목 점수는 상위 24건 실측 기준 그대로 두고, AI 티는 `hold` 표시만 한다. 점수를 섞으면 기존 기준선·이력과 비교가 안 된다.

## 5. 쓰는 법

```
# 웹앱
점검 탭(#/lint) → 제목·본문·사진 수·검색어 넣고 [8항목 + AI 티 검사]
제작 탭(#/create/blog) → [바로 만들기] 뒤 'AI 티 8패턴 · D.I.A.+' 줄에서 같은 판정

# 노트북·클로드 코드
python3 tools/blog_lint_cli.py draft.md --keyword 봉명동맛집,삼겹살
python3 tools/blog_lint_cli.py draft.md --json          # CI·오더용
python3 tools/blog_lint_cli.py draft.md --strict        # AI 티 '발행 보류'도 실패(1)
```

## 6. 하지 않는 것

- **AI 탐지 회피용 문장 세탁을 자동으로 하지 않는다.** 고치는 것은 글쓴이(성래 님)다. 린터는 세기만 한다. 번역투(8번째 패턴)도 마찬가지로 **세기만** 한다.
- 판정은 기계적으로 센 값만 본다. 톤의 좋고 나쁨, 정보의 진위, 겪지 않은 경험 여부는 사람이 본다(B8: 겪지 않은 경험 지어내기 금지 — 도구로 해결되지 않는다).
- `#/lint` 밖에서 저장·발행을 건드리지 않는다. 초안은 브라우저 localStorage에만 남는다.
